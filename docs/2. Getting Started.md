# Getting Started

We’ve provided a [project starter repository](https://github.com/udacity/cd0583-project-starter-file) that contains template scripts for each step of the project, along with sample datasets for model training. You can clone or download the repository to set up the project in your environment.

**Using Azure DevOps (optional)**: You may use Azure Repos for source control while completing this project. Follow **Import the ND0821 course repository** in the GitHub to Azure DevOps Translation Guide. When prompted for the source Clone URL, use `https://github.com/udacity/cd0583-project-starter-file`. If your organization blocks repository imports, clone the public starter repository locally and push it to an empty Azure Repos repository. Keep the starter directory structure unchanged, use only organization-approved authentication, and never commit credentials or proprietary data.

## The Workspace

You can complete the project in the Udacity Workspace, which contains all required computing resources. You may instead work in a compatible local environment and use GitHub or Azure Repos for source control. The instructions below use the Workspace paths as examples. If you work locally, preserve the same project-relative folder structure and confirm that every required script and output file is included in your final ZIP.

Use the preinstalled `ml` Conda environment for all project commands in the Workspace. If your terminal prompt does not show `(ml)`, run `conda activate ml`. Required Python packages are already installed; no additional installation is needed.

Run the project scripts from the repository root (`/workspace/cd0583-project-starter-file/` in the Workspace). Paths such as `practicedata`, `sourcedata`, and `testdata/testdata.csv` in the project instructions and `config.json` are relative to this root.

Your Workspace has eight locations you should be aware of:

- `/workspace/cd0583-project-starter-file/` — the root directory of the project starter files. This is the default location when the Workspace opens.
- `/workspace/cd0583-project-starter-file/practicedata/` — contains datasets for practice.
- `/workspace/cd0583-project-starter-file/sourcedata/` — contains data used to train your models.
- `/workspace/cd0583-project-starter-file/ingesteddata/` — stores compiled datasets generated by the ingestion step.
- `/workspace/cd0583-project-starter-file/testdata/` — contains data for testing your models.
- `/workspace/cd0583-project-starter-file/models/` — stores trained models for production use.
- `/workspace/cd0583-project-starter-file/practicemodels/` — stores models created during practice.
- `/workspace/cd0583-project-starter-file/production_deployment/` — contains final deployed models.

### Important notes about the Workspace

Files in the `/workspace/` directory are saved automatically. However, after about 30 minutes of inactivity, the Workspace will go to sleep - for example, if the tab is closed or not in use. When you return, your files will be restored to your most recent work, but any open files or running terminal sessions will be reset.

Azure Repos is a source-control option, not a replacement for the project runtime. If you work outside the Workspace, you are responsible for providing a compatible Python environment, installing the dependencies in `requirements.txt`, and generating all required output files.

## Starter Files

The starter contains 10 Python scripts, one configuration file, one requirements file, and five datasets.

### Python files

- `training.py` — trains an ML model.
- `scoring.py` — scores an ML model.
- `deployment.py` — deploys a trained ML model.
- `ingestion.py` — ingests new data.
- `diagnostics.py` — measures model and data diagnostics.
- `reporting.py` — generates reports about model metrics.
- `app.py` — contains API endpoints.
- `wsgi.py` — supports API deployment.
- `apicalls.py` — calls your API endpoints.
- `fullprocess.py` — determines whether a model needs to be redeployed and calls the other Python scripts when needed.

### Datasets

The following fabricated datasets contain information about hypothetical corporations. They are also available in the Workspace.

- `dataset1.csv` and `dataset2.csv` in `practicedata`
- `dataset3.csv` and `dataset4.csv` in `sourcedata`
- `testdata.csv` in `testdata`

### Other files

- `requirements.txt` records the current versions of the modules used by the scripts.
- `config.json` contains the file and directory settings used by the project scripts.
